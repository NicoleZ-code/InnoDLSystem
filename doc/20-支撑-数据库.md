# 20 · 支撑设施：数据库

> 路径：`code/database/`（`migrations/`、`schemas/`、`seed/`）
> 运行时执行方：`apps/api-server/src/infrastructure/database/{postgres,extended,sqlite-test}.ts`

## 1. 迁移文件

### `migrations/001-core.sql` — 16 张表 + 1 个索引

全部 `CREATE TABLE IF NOT EXISTS`，主键多为 `text`，时间戳 `bigint`，业务详情用 `jsonb`：

| 表 | 要点 |
| --- | --- |
| `schema_migrations` | `version integer PK, applied_at bigint` |
| `regions` | `id, name` |
| `assets` | `id, name, type, region→regions, longitude/latitude/height/voltage/capacity, status` |
| `power_lines` | `from_id/to_id → assets ON DELETE RESTRICT`，`CHECK(from_id<>to_id)` |
| `telemetry` | `tick integer PK, timestamp, document jsonb` |
| `alarms` | `id, asset_id, timestamp, status, acknowledged_at, note, document jsonb` |
| `app_state` | `key PK, value jsonb`（存模拟时钟、revision、已发布场景快照） |
| `audit_log` | `id bigserial, action, entity_id, timestamp, details` |
| `users` / `sessions` | scrypt `password_hash`；`token_hash PK` |
| `protection_events` / `protected_assets` | 活动与保障对象多对多 |
| `work_orders` | 关联 alarm/asset/event，`feedback DEFAULT ''` |
| `scenes` | `configuration jsonb, revision DEFAULT 1` |
| `asset_model_bindings` | `asset_id PK, model_uri` |
| `measurement_points` | `id, asset_id, name, unit, quality DEFAULT 'simulated'` |

唯一索引：`telemetry_timestamp ON telemetry(timestamp)`。

### `migrations/002-domains.sql` — 新增 17 张表 + 加列 + 部分唯一索引

新建：`alarm_rules`、`telemetry_history`（`PRIMARY KEY(point_id,ts) PARTITION BY RANGE(ts)`）、`telemetry_history_default`（`PARTITION OF ... DEFAULT`）、`telemetry_latest`、`topology_nodes`（`electrical_code UNIQUE`）、`topology_edges`（`state CHECK IN ('CLOSED','OPEN','UNKNOWN')`）、`topology_versions`、`protection_plans`、`work_order_logs`、`scene_models`、`scene_bindings`、`scene_layers`、`camera_presets`、`roles`、`user_scopes`、`refresh_sessions`、`idempotency_keys`。

关键 ALTER：

- `users_role_check` 先 DROP 再 ADD，角色扩展为 5 个：`admin / protection_manager / supervisor / operator / viewer`；
- `measurement_points` 加 `metric`(默认 voltage)、`enabled`(默认 true)；
- `work_orders` 加 `version DEFAULT 1`（乐观锁）；`alarms` 加 `closed_at`、`rule_id`、`point_id`；
- `assets` 加 `parent_id`；`regions` 加 `parent_id`、`boundary jsonb`；
- **部分唯一索引** `alarms_one_active_rule ON alarms(rule_id) WHERE status='active' AND rule_id IS NOT NULL` —— 保证一条规则最多一条活动告警。

### `migrations/003-spatial.sql` — PostGIS（条件执行）

`CREATE EXTENSION IF NOT EXISTS postgis`；`assets` 加 `location geometry(Point,4326)` + GiST 索引；触发器函数 `sync_asset_location()` 在 INSERT/UPDATE 经纬度时用 `ST_SetSRID(ST_MakePoint(...),4326)` 同步；回填已有行。

> SQL 文件本身**没有条件判断**。是否执行由 `extended.ts:17-22` 决定：`SELECT name FROM pg_available_extensions WHERE name='postgis'`，有结果才执行。本机 PostgreSQL 14 无 PostGIS，故只验证了普通 PG 路径；Compose 使用 `postgis/postgis:16-3.4` 镜像。`assets.routes.ts` 在检测不到 `location` 列时，把 `ST_Intersects(ST_MakeEnvelope(...))` 降级为标量 `longitude/latitude BETWEEN`。

## 2. 种子：三个 SQL 都是纯 DDL

**`001/002/003` 不含任何 `INSERT`**。基础种子由服务端代码在 `pg_advisory_xact_lock(583177)` 事务内按 `schema_migrations.version=1` 幂等注入：

| 阶段 | 文件 | 注入内容 |
| --- | --- | --- |
| `openPostgres()` | `postgres.ts:45-115` | 执行 `001-core.sql`；若无 version=1 → `regions`(3)、`assets`(8，来自 `shared-utils`)、`power_lines`(7)、`telemetry(0)`、`app_state(simulation/revision)`、`protection_events('ciie-2026')`、`protected_assets`(core 资产)、`scenes`(city/grid/venue/equipment)、`asset_model_bindings('venue')`、每资产 1 个 `-voltage` 测点 → 写 version=1 |
| `extendDatabase()` | `extended.ts:8-57` | 同一把锁 → `002-domains.sql` → 条件 `003-spatial.sql` → `ON CONFLICT DO NOTHING` 注入 5 个 `roles`、`topology_nodes/edges`、每资产 `-temperature` 测点、8 条 `alarm_rules`（`gt 55 attention`）、2 条 `scene_models`、`scene_bindings`、`scene_layers`、`camera_presets`（`121.302/31.188/2000, heading 15, pitch -48, duration 2`） |

合计基础规模：**8 资产 / 7 线路 / 16 测点 / 8 规则 / 1 保电活动 / 4 场景**。

SQLite 适配器（`sqlite-test.ts`）不读迁移文件，改为内联 SQL 自建 8 张表（`document` TEXT(JSON) 列），种子只含 regions/assets/lines/telemetry(0)/app_state，**不含 protection/scenes/measurement_points/roles**。

## 3. Prisma 双轨（职责分离，不是重复建表）

`schemas/schema.prisma`（27 行）只有 2 个 model：

| model | 映射 | 字段 |
| --- | --- | --- |
| `MeasurementPoint` | `@@map("measurement_points")` | `id, assetId, name, unit, quality, metric, enabled` |
| `AlarmRule` | `@@map("alarm_rules")` | `id, pointId, name, operator, threshold, severity, enabled` |

`datasource db` 为 `postgresql` + `env("DATABASE_URL")`。**Prisma 不负责建表**，`pnpm db:generate` 只生成客户端；唯一使用处是 `apps/api-server/src/modules/telemetry/telemetry.routes.ts`，用 `new PrismaClient({datasources:{db:{url: ...&schema=<schema>}}})` 做测点/规则的 CRUD 与查询。其余全部走 `pg` 原生 SQL。

`code/docs/database/README.md` 明确：「Prisma schema 用于测点与规则映射；空间和分区 DDL 由 SQL 管理，不用 `prisma db push` 代替迁移」。`apps/api-server/prisma/` 是空目录。

## 4. 演示扩展种子

`seed/demo.sql`（13 行）+ `seed/run.mjs`（10 行），入口 `pnpm seed:demo`（`node --env-file-if-exists=.env database/seed/run.mjs`）：

| 数据 | 数量 | 编码规律 |
| --- | ---: | --- |
| 变电站 | 12 | `demo-station-1..12`（substation，110kV/160） |
| 配电设备 | 300 | `demo-device-1..300`（switchgear/transformer 交替，10kV，按 `(n-1)%12+1` 挂站） |
| 馈线 | 120 | `demo-line-1..120`（10kV，load 45） |
| 测点 | 800 | `demo-point-1..800`（柜内温度 °C / 运行电压 kV 交替） |
| 拓扑节点/边 | 按 `id LIKE 'demo-%'` 生成 | — |

`run.mjs` 用 `pg.Pool` + 单事务执行整个 SQL，异常 ROLLBACK。

**幂等策略**：所有台账插入 `INSERT ... SELECT ... ON CONFLICT(id) DO NOTHING`，固定 `demo-*` 编码可重复执行。**但未完全幂等**：`UPDATE app_state`（revision +1）与 `INSERT INTO audit_log('demo.seed', ...)` 每次执行都会累积；`tests/postgres.test.ts:269-280` 连跑两次后只校验 12/300/120/800 数量不变。

数字与方案 B 原文第十二章「12 站 / 300 设备 / 120 线路 / 800 测点」逐项对应。

## 5. 设计取舍与已知缺口

1. **SQL 与代码双真源**：DDL 在 `database/migrations/`，种子在 `api-server` TypeScript 里，`README.md` 描述的「基础种子由迁移版本控制」实际是「由 `schema_migrations` 版本表控制的运行时代码注入」。排障时需要同时看两处。
2. **`telemetry_history` 只有 DEFAULT 分区**：`docs/database/README.md` 建议按月分区，但代码无自动建子分区逻辑，全部数据落 `telemetry_history_default`。
3. **`001-core.sql` 索引极少**（只有 1 个），高频查询（assets by region、alarms by status、sessions by expires_at）无专门索引；演示规模下无感，真实数据量下需补。
4. **Prisma 与 `pg` 连接串处理不同**：`openPostgres` 对 schema 名做正则白名单，Prisma 侧把 `schema=` 追加到 URL 且用 `userInfo().username` 补用户名，未复核该白名单。
5. **会话表无定期清理**：`sessions` 仅登录时删过期行，`refresh_sessions` 只删当前 token，长期运行会膨胀。
6. **SQLite 只是仓储测试适配器**：8 张表 + JSON 文档列，与生产 33 张表结构不同，不能用于验证 SQL 迁移或 PostGIS 行为。
7. **无回滚脚本**：全部迁移为 `CREATE ... IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` 的前向幂等，没有 down 迁移。
