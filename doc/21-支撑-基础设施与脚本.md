## 2. `infra/Dockerfile`（20 行，3 阶段 / 2 target）

```dockerfile
FROM node:22-bookworm-slim AS build
  # apt: openssl ca-certificates；corepack prepare pnpm@10.11.0
  COPY . . → pnpm install --frozen-lockfile
  → DATABASE_URL=postgresql://innodl:build-only@localhost/innodl_system pnpm --filter @innodl/api-server db:generate
  → ENV ADMIN_BASE=/admin/ → pnpm build
FROM build AS api       # NODE_ENV=production, WORKDIR /app/apps/api-server, EXPOSE 8787, CMD node dist/main.js
FROM nginx:1.27-alpine AS nginx
  # COPY infra/nginx/default.conf
  # COPY --from=build twin-screen/dist → /usr/share/nginx/html
  # COPY --from=build admin-web/dist → /usr/share/nginx/html/admin
```

> `ADMIN_BASE=/admin/` 在构建期注入，使后台 SPA 的 `BrowserRouter basename` 与静态资源前缀匹配容器路径。

## 5. `code/scripts/`

### `dev.mjs`（35 行）

```js
['@innodl/api-server','@innodl/twin-screen','@innodl/admin-web']
  .map(name => spawn('pnpm', ['--filter', name, 'dev'], {stdio:'inherit', detached: !win32}))
```

- **脚本自身不指定端口**，端口由各 app 决定（8787 / 5187 / 5189）。
- 退出逻辑：`closing` 防重入；任一子进程 `error` → `stop(1)`，任一 `exit` → `stop(code)`；`SIGINT/SIGTERM` → `stop()`；非 win32 用 `process.kill(-child.pid,'SIGTERM')` **杀整个进程组**（因 `detached:true`），避免 Vite 残留。
- `stop(code)` 带完整 JSDoc（`@param code 根进程退出码` / `@returns 无返回值，结束开发进程组`）。

### `copy-cesium.mjs`（11 行）

用 `createRequire` 以 `apps/twin-screen/package.json` 为基准解析 `cesium/package.json` → `Build/Cesium`；把 `Workers`、`Assets`、`Widgets`、`ThirdParty` 四个目录复制到 `apps/twin-screen/public/cesium/`（Vite 将 `public/` 映射到站点根，配合 `CESIUM_BASE_URL='/cesium/'`）。

条件为 `if (!existsSync(dest)) cpSync(...)` —— **幂等但非更新**：升级 Cesium 后旧静态资源不会刷新，需手动删除目录。不复制 `Cesium.js` 主包（由 Vite 从 npm 打包），`widgets.css` 由 `createCity.ts` 直接 import。

被 `twin-screen` 的 `dev` 与 `build` 脚本前置调用；`typecheck` 不调用。

### `setup-hooks.mjs`（5 行）

```js
if (existsSync('.git')) execFileSync('pnpm', ['exec','husky'], {stdio:'inherit'});
else console.log('Husky 配置已就绪；在本目录初始化 Git 后运行 pnpm prepare 启用');
```

只做条件安装，避免修改父级仓库的 hooks。**lint-staged 配置不在脚本里**，分散在根 `package.json` 的 `lint-staged` 字段与 `.husky/pre-commit`（单行 `pnpm exec lint-staged`）。

## 6. 设计取舍与已知缺口

1. **Docker 部署未验证**：`code/README.md` 明确「当前机器未完成 Docker 守护进程运行验证，不能视为已部署」；`minio` 与 `nginx` 无健康检查，`api` 对 minio 只 `service_started`（MinIO 可能尚未就绪）。
2. **`api` 容器同时托管大屏静态资源**：`app.ts` 用 `@fastify/static` 托管 `twin-screen/dist`，Nginx 又拷了一份该 dist 到自己的 root —— 两处来源重复，`/` 走 Nginx 静态、`/api/` 走 API，实际不冲突但增加镜像体积。
3. **admin-web 不由 API 托管**：开发态与容器态都必须有独立静态宿主（Vite 或 Nginx `/admin/`）。
4. **`ADMIN_BASE` 只在 Dockerfile 构建期设置**：本地 `pnpm build` 产出的 admin-web dist 若直接用于 `/admin/` 路径会资源 404，需显式设置该环境变量。
5. **无 TLS 终止配置**：`default.conf` 只监听 80；README 要求正式 HTTPS 环境设置 `COOKIE_SECURE=true` 并在入口终止 TLS，但仓库未提供对应 conf。
6. **`copy-cesium.mjs` 的版本陷阱**（§5）以及 `public/cesium/` 被 `.gitignore` 忽略，克隆后首次 `dev`/`build` 会重新生成。
7. **凭据管理**：`setup-env.mjs` 生成的 4 个随机凭据仅存本地 `.env`（`0o600`），`compose.yaml` 用 `:?` 强制校验；但 `code/.env.example` 中含 `BOOTSTRAP_ADMIN_PASSWORD=` 空值示例，若被误用作生产配置会触发服务端随机口令写入 `bootstrap-admin.txt`。
8. **端口分散定义**：5187 硬编码在 twin-screen、5189 在 admin-web、8787 在 config.ts、8790/5198/55432 在测试与 compose 中，无集中端口清单文件（本文档 01 的端口表可作索引）。
