# 01 · 使用文档

> 适用对象：需要把项目跑起来、验证演示闭环、执行测试或部署容器的开发/验收人员。
> 所有命令在 `InnoDLSystem/code/` 目录下执行（下文简称「仓库根」）。

## 1. 环境要求

| 项 | 要求 | 依据 |
| --- | --- | --- |
| Node.js | ≥ 22.17.0（`engines.node`） | `package.json` |
| pnpm | 10.11.0（`packageManager`） | `package.json` |
| PostgreSQL | ≥ 14，需预先创建数据库 `innodl_system` | `README.md`、`config.ts` |
| Docker（可选） | 需 Docker Compose v2 与运行中的 daemon | `infra/compose.yaml` |
| Chromium（E2E 可选） | `pnpm exec playwright install chromium` | `playwright.config.ts` |

> **推荐本地原生方式**：PostgreSQL + `pnpm dev` 已于 2026-11-04 在本机完整验证通过（见 §10）。容器方式可选，见 §7；`code/README.md` 中「未完成 Docker 守护进程运行验证」是早期说明。

## 2. 首次安装与启动

```sh
cd A-project/3D/InnoDLSystem/code
pnpm install
pnpm run setup             # 生成 .env（已存在则不覆盖）
# 在 .env 中确认 DATABASE_URL 指向已创建的 innodl_system
pnpm db:generate           # 生成 Prisma Client（测点/规则两张表）
pnpm dev                   # 并行启动 3 个 app
```

> ⚠️ **必须写 `pnpm run setup`，不要写 `pnpm setup`**。pnpm 10 自带同名内置命令 `pnpm setup`（配置 shell 的 `PNPM_HOME`），会抢先执行，**不会生成 `.env`**。本机实测踩过此坑：它只往 `~/.zshrc` 追加了 pnpm 配置块。保险写法：`node infra/scripts/setup-env.mjs`。

`pnpm run setup` 由 `infra/scripts/setup-env.mjs` 执行，生成 `code/.env`（权限 `0o600`），包含 4 个随机凭据：

- `POSTGRES_PASSWORD`、`REDIS_PASSWORD`、`MINIO_ROOT_PASSWORD`：各 24 字节 hex（48 位）
- `BOOTSTRAP_ADMIN_PASSWORD`：18 字节 base64url（24 位），首次启动创建 `admin` 时使用

同时写入 `API_HOST=127.0.0.1`、`API_PORT=8787`、`COOKIE_SECURE=false`、`VITE_DATA_MODE=server`、`DATABASE_URL=postgresql://<当前系统用户>@localhost:5432/innodl_system`。

**首次 API 启动**会执行幂等迁移并注入基础种子：8 个保障对象、7 条线路、16 个测点、8 条规则、1 个保电活动 `ciie-2026`、4 个场景。需要扩展演示规模时，在首次启动完成后执行：

```sh
pnpm seed:demo    # 增加 12 站 / 300 设备 / 120 线 / 800 测点，保留原有台账
```

### 访问入口

| 服务 | 地址 | 端口来源 |
| --- | --- | --- |
| 三维指挥大屏 | <http://localhost:5187/twin/overview> | `apps/twin-screen/vite.config.ts` 固定 5187，`strictPort: true` |
| 综合业务后台 | <http://localhost:5189/dashboard> | `ADMIN_PORT`，默认 5189（5188 被本机其他项目占用） |
| API 健康检查 | <http://localhost:8787/api/v1/health> | `API_PORT`，默认 8787 |
| Swagger UI | <http://localhost:8787/api-docs> | `@fastify/swagger-ui` |
| 容器统一入口 | <http://localhost:8080/>、<http://localhost:8080/admin/> | `infra/compose.yaml` nginx `8080:80` |

### 管理员登录

- 用户名：`admin`（大屏 `Login.tsx` 与后台登录表单均以此为默认值）。
- 密码：`pnpm run setup` 写入 `.env` 的 `BOOTSTRAP_ADMIN_PASSWORD`。
- **但若数据库已初始化过（已有 `users` 表数据），修改该环境变量不会重置已有密码** —— 此时实际生效的是首次创建时写入 `apps/api-server/data/bootstrap-admin.txt` 的密码。
- 本机实测：数据库已有 33 张表与 `admin` 账号，因此已把 `.env` 的 `BOOTSTRAP_ADMIN_PASSWORD` 同步为 `bootstrap-admin.txt` 中的值，两处一致，可直接登录。
- 浏览器代码中不内置任何密码。

登录态：短效访问令牌存 `sessionStorage['innodl-token']`（`Authorization: Bearer`），7 天有效的刷新令牌在 `innodl-refresh` HttpOnly Cookie 中。访问令牌 15 分钟过期，401 时由 `@innodl/api-client` 自动调 `/api/v1/auth/refresh` 并重试一次。

## 3. 常用命令

| 命令 | 作用 |
| --- | --- |
| `pnpm dev` | `scripts/dev.mjs` 并行启动 api-server / twin-screen / admin-web |
| `pnpm dev:web` / `pnpm dev:admin` / `pnpm dev:api` | 单独启动某个 app |
| `pnpm build` | `turbo run build`（按依赖顺序构建所有包） |
| `pnpm lint` / `pnpm typecheck` / `pnpm test` | ESLint / TypeScript / Vitest |
| `pnpm format` / `pnpm format:check` | Prettier 写入 / 检查 |
| `pnpm test:e2e` | Playwright E2E（需先安装 Chromium） |
| `pnpm mock` | 运行 `tooling/mock-telemetry`，向 stdout 输出 NDJSON |
| `pnpm db:generate` | `prisma generate --schema database/schemas/schema.prisma` |
| `pnpm infra:up` / `pnpm infra:down` | Docker Compose 启动 / 停止（保留卷） |

> `pnpm dev` 用 `detached` 进程组启动子进程，退出时按进程组发 `SIGTERM`，避免残留 Vite 进程。

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `API_HOST` / `API_PORT` | `127.0.0.1` / `8787` | 后端监听；容器内由 compose 覆盖为 `0.0.0.0` |

| `VITE_DATA_MODE` | `server` | 仅当显式设为 `offline` 时，大屏使用浏览器本地演示数据，不连后端 |

| `TEST_DATABASE_URL` | 本机 `innodl_system` | 集成测试与 E2E 的目标库 |

## 5. 演示业务闭环（推荐验收路径）

数据来自统一后端，闭环如下：

1. 后台 `重点保电 → 保电活动` 中，编辑 `ciie-2026`，把保障对象绑定到 `station-a` 等资产。
2. 打开大屏 <http://localhost:5187/twin/protection/ciie-2026>，地址直达会请求 `/api/v1/protection-events/ciie-2026` 并只显示保障对象。
3. 模拟时钟推进到 **tick 30–54**：`station-a` 温度越限（规则 `>55`），后端 `measurement.service.ts` 生成 `alarm.created`，通过 WebSocket 广播；大屏自动切到 `venue` 模式并选中告警资产。
4. 后台 `告警处置 → 告警事件` 点击「确认」，或大屏「数据维护」弹窗中确认并「定位」。
5. 后台 `运维工单` 新建工单，依次执行 **指派 → 开始处理 → 提交反馈 → 主管复核关闭**。状态流转走 `POST /api/v1/work-orders/:id/{assign|start|submit|review}`，带 `version` 乐观锁。
6. tick 55 温度恢复，活动告警自动 `resolved`；复核关闭成功（有未恢复告警时后端返回 409）。
7. `分析报表 → 保电报告` 查看汇总并导出 JSON；活动归档。

**修改公共模拟时钟**：管理员 `PATCH /api/v1/simulation`（body `{"tick":35}` 或 `{"playing":false}`）。大屏底部时间轴是**当前浏览器只读回放**（`GET /api/v1/telemetry/replay?tick=N`），不会改变服务端时钟。

**离线演示**：设置 `VITE_DATA_MODE=offline` 后，大屏用 `shared-utils` 的 `telemetryAt(tick)` 每秒本地推进，不建 WebSocket；此时「数据维护」的保存/删除按钮因 `connection !== 'online'` 被禁用。

## 6. 测试

```sh
pnpm test                                  # Vitest：4 个测试文件
pnpm exec playwright install chromium      # 首次
pnpm test:e2e                              # Playwright：4 个 spec
```

- 集成测试 `tests/postgres.test.ts` 连接 `TEST_DATABASE_URL`，每次创建独立 schema `test_innodl_<timestamp>` 并在结束后 `DROP SCHEMA ... CASCADE`。
- Playwright 独占端口 **5187 / 5198 / 8790**，且 `reuseExistingServer: false`，**运行前请先关闭本项目开发服务**。
- E2E 后端使用独立 schema `e2e_innodl_<pid>`、独立口令 `E2E-Only-InnoDL-2026!`，退出时删 schema。
- 浏览器以 SwiftShader 软件 WebGL 启动（`--use-angle=swiftshader`），视口固定 1920×1080。
- 验收产物写入 `code/docs/browser-verification.json` 与 `code/docs/*.png`。

## 7. 容器部署

```sh
pnpm setup
pnpm infra:up       # docker compose --env-file .env -f infra/compose.yaml up --build -d
pnpm infra:down     # down，保留卷
```

Compose 名称 `innodl-power`，5 个服务：`postgres`(postgis/postgis:16-3.4，宿主 `127.0.0.1:55432`)、`redis`、`minio`、`api`、`nginx`(8080:80)。4 个命名卷独立持久化 Postgres 数据、Redis、模型与 API 本地数据。

Nginx 路由：`/api/`、`/api-docs`、`/ws/`（含 WebSocket Upgrade）、`/models/uploaded/` 反代到 `api:8787`；`/admin/` 指向后台 SPA，其余走大屏 SPA。

正式 HTTPS 环境需设置 `COOKIE_SECURE=true` 并在入口终止 TLS。模型上传/下载经过同源网关，浏览器不依赖 Docker 内部主机名。

## 8. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 大屏一直显示「后端连接失败」 | 确认 API 8787 已启动、`.env` 的 `DATABASE_URL` 可用；`VITE_DATA_MODE` 是否被误设为 `offline` |
| 后台停在「正在加载统一业务数据」 | `catalog` 查询 `enabled: !!user.data`，`/api/v1/auth/me` 或 `/api/v1/catalog/shanghai` 失败会阻塞全部页面 |
| 登录反复跳回 | 刷新 Cookie 的 `Path=/api/v1/auth`；跨域独立部署时无 CORS 配置，须同源或走代理 |
| 端口被占用 | 三个 app 都是 `strictPort: true`，不会自动换端口；大屏 5187 不可配，后台用 `ADMIN_PORT` |
| 模型上传后不显示 | 上传是三步：申请签名 URL → PUT → `/complete`；还需在 `/scenes` 配置页「发布」后，catalog 事件才会推送新绑定 |
| Cesium 报静态资源 404 | `pnpm dev:web` / `build` 会先跑 `scripts/copy-cesium.mjs`；该脚本在目标目录已存在时**跳过**，升级 Cesium 后需手动删除 `apps/twin-screen/public/cesium/` 再启动 |
| `pnpm test:e2e` 启动失败 | 关闭占用 5187/5198/8790 的开发服务；确认已安装 Chromium |
| 执行 `pnpm setup` 后 `.env` 没生成 | 被 pnpm 10 内置命令拦截；改用 `pnpm run setup` 或 `node infra/scripts/setup-env.mjs` |
| 刚启动 `pnpm dev` 时前端代理返回 502 | API 需先跑迁移/种子，比 Vite 慢几秒；等 `curl localhost:8787/api/v1/health` 返回 200 后再刷新页面 |
| 管理员密码不对 | 数据库已初始化时 `.env` 的新随机密码不生效；用 `apps/api-server/data/bootstrap-admin.txt` 中的密码 |
| Git 钩子未生效 | `scripts/setup-hooks.mjs` 仅在 `code/.git` 存在时安装 Husky；当前目录尚未初始化 Git |

## 9. 交付边界

正式城市 GIS、站房 BIM、实物设备模型和生产采集接口尚未提供。当前空间模型由 `tooling/model-converter/generate-demo-models.py` 程序化生成，数值标记 `simulated` / `SIMULATED` / `isDemoData: true`，**不是视频对应的真实测绘模型**。通用 BIM / 3D Tiles 转换、移动端、完整场景编辑器不属于当前交付能力；长时运行、目标硬件 FPS 与真实生产接入需另行验收。
