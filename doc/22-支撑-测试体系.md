## 4. 三层数据库隔离

| 层 | 机制 |
| --- | --- |
| SQLite 单元 | `backend.test.ts` 默认 `:memory:`；持久化用例用 `mkdtempSync('innodl-api-*')/app.sqlite`，`afterEach` 关实例、`finally rmSync(recursive,force)` |
| PG 集成 | `schema = test_innodl_${Date.now()}`，`openPostgres` 会 `CREATE SCHEMA IF NOT EXISTS` 并设 `search_path=<schema>,public`；`afterAll` `DROP SCHEMA ... CASCADE` |
| E2E | `e2e_innodl_${pid}` + 独立端口 8790 + 独立口令；退出 `DROP SCHEMA ... CASCADE` |

迁移自身也幂等：`CREATE ... IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` / `ON CONFLICT DO NOTHING` + `pg_advisory_xact_lock(583177)` + `schema_migrations` 版本表。

## 6. 设计取舍与已知缺口

1. **测试覆盖偏后端**：11 个 PG 集成 it 覆盖了认证、状态机、RBAC、区域授权、上传发布、幂等；前端只有 4 个 E2E spec，且主要做「文本/元素存在」断言，无视觉回归、无 API 契约测试、无单测（React 组件零单测）。
2. **E2E 依赖真实 GPU 渲染路径**：用 SwiftShader 软件 WebGL，耗时较长（单 spec 最长 180s），且 `workers:1`、`reuseExistingServer:false`，不适合高频本地执行。
3. **硬编码 E2E 口令**：`E2E-Only-InnoDL-2026!` 写在 `e2e-server.ts` 与 `auth.ts` 两处，仅用于临时 schema，可接受但需注意别误用于开发库。
4. **端口冲突风险**：`dashboard.spec.ts` 用 5187（与大屏开发端口相同），若 `pnpm dev` 未关闭，`reuseExistingServer:false` 会直接失败。
5. **断言含硬编码业务值**：经度 `121.285`、区域「共 2 个保障对象」、文案「诸光—会展 Ⅰ线」等与演示种子强绑定，改种子会连带改测试。
6. **SQLite 测试模式覆盖面窄**：`backend.test.ts` 只覆盖无 `if(pg)` 守卫的少数路由，不能作为全后端回归（见 [05 文档](05-子项目-api-server.md) §3）。
7. **`demo.sql` 幂等断言不完整**：只校验 4 个数量，`app_state.revision` 与 `audit_log` 的累积未被检出。
8. **无覆盖率门槛、无 CI 配置**：仓库内未见 `coverage` 配置或 GitHub Actions / CNB 流水线文件；`pnpm lint/typecheck/test` 需人工执行。
9. **`test-results/` 与 `.turbo/` 日志**：`code/test-results/` 已存在运行残留，被 `.gitignore` 与 ESLint ignores 屏蔽。
